## 0. 先说结论

browser-use **没有**给每种控件都加命令。它的策略是三招：

1. **让模型看见变化**：新出现的元素打 `*` 号，模型一眼就知道"刚才那一下弹出了什么"；
2. **让模型看懂控件**：复杂控件在快照里附带"说明书"（范围、当前值、前几个选项）；
3. **让动作自己适应控件**：同一个 `input` 动作，遇到日期框、滑块就自动换成直接赋值。

只有一种情况加了专门命令：**原生 `<select>`**，因为它点开的菜单根本不在 DOM 里。

---

## 1. 第一招：`*[` 新元素标记

### 比喻：大家来找茬

你玩过"找不同"游戏吧：两张几乎一样的图，找出哪里变了。人很难一眼找出来，模型也一样。一个页面有 200 个元素，点了一下以后多了 8 个，模型要自己对比前后两张快照才知道，又费 token 又容易漏。

browser-use 的做法是**直接把不同的地方圈出来**：

```
[3501]<div role=combobox aria-expanded=true />
	选择颜色
*[3620]<li role=option />
	午夜色
*[3621]<li role=option />
	星光色
*[3622]<li role=option />
	蓝色
```

带 `*` 的就是这一步新出现的元素。

### 实现

```python
# _assign_interactive_indices_and_mark_new_nodes 里
elif self._previous_node_ids:
    current_node_id = (str(node.original_node.session_id), node.original_node.backend_node_id)
    if current_node_id not in self._previous_node_ids:
        node.is_new = True
```

就是一个集合差：**这次快照的节点 ID 集合 − 上次快照的节点 ID 集合**。因为第 2 站讲的编号是稳定的"学号"，这个对比才成立。用"座位号"根本没法对比。

系统提示词里专门教了模型怎么用它：

> Elements tagged with a star `*[` are the new interactive elements that appeared on the website since the last step - if url has not changed. Your previous actions caused that change. Think if you need to interact with them, e.g. after input you might need to select the right option from the list.

注意 "if url has not changed"：页面跳转了，所有元素都是新的，打 `*` 没有意义。

### 这一招解决了哪些控件

| 控件 | 模型怎么操作 |
|---|---|
| **div 模拟的下拉框**（淘宝京东的规格选择基本都是） | `click` 展开 → 看到一堆 `*[` 选项 → `click` 选中 |
| **自动补全输入框** | `input` 输入 → 看到 `*[` 建议项 → `click` 选中（第 1 站讲过，`input` 返回值会提示"不要按回车，去点建议项"） |
| **悬停菜单、展开面板** | `click` 展开 → 看到 `*[` 子菜单 |
| **弹窗** | 某个动作后突然多了一堆 `*[`，其中有"关闭"按钮 → `click` 或 `send_keys("Escape")` |
| **"加载更多"** | `click` 后列表末尾多了 `*[` 商品 |

**一个 `click` + 一个 `*` 标记，就覆盖了绝大多数自定义控件**，不需要专门的命令。

## 2. 第二招：复合控件附带"说明书"

有些控件，光看标签模型不知道怎么用。比如 `<input type="range">`，模型只看到一个 input，不知道它的范围是多少、现在是多少。

### 比喻：家电的铭牌

你看到一台空调，不知道它的功率、电压。但空调背后贴着一块铭牌，写着"220V / 1.5 匹"。browser-use 给复杂控件**贴铭牌**，叫 `compound_components`：

```
[3488]<input type=range compound_components=(name=Value,role=slider,min=0,max=100) />
[3490]<select compound_components=(name=Dropdown Toggle,role=button),(name=Options,role=listbox,count=12,options=128GB|256GB|512GB|1TB) />
[3492]<input type=number compound_components=(name=Increment,role=button),(name=Decrement,role=button) />
[3494]<input type=file compound_components=(name=Browse Files,role=button),(name=File Selected,role=textbox,current=None) />
```

`_add_compound_components` 处理的控件：

| 控件 | 附带的信息 |
|---|---|
| `input[type=range]` 滑块 | min、max |
| `input[type=number]` | 有加减按钮 |
| `input[type=color]` | 有十六进制输入框和取色按钮 |
| `input[type=file]` | 当前选了什么文件 |
| `<select>` | 选项总数 + **前 4 个选项** |
| `<details>`、`<audio>`、`<video>` | 各自的子控件 |

### 一个反例：日期框**故意不加**说明书

源码里有段注释很有意思：

```python
# NOTE: For date/time inputs, we DON'T add compound components because:
# 1. They confuse the model (seeing "Day, Month, Year" suggests DD.MM.YYYY format)
# 2. HTML5 date/time inputs ALWAYS require ISO format (YYYY-MM-DD, HH:MM, etc.)
# 3. The placeholder attribute clearly shows the required format
# 4. These inputs use direct value assignment, not sequential typing
```

一开始给日期框加了"日/月/年"三个子组件，结果模型以为要按"日.月.年"的格式输入，反而输错了。**给模型的信息不是越多越好，误导性的信息比没有更糟。** 这条经验对我们做页面压缩很重要。

## 3. 第三招：动作自己适应控件

还是第 2 站讲过的 `_requires_direct_value_assignment`：

```
input(index=3488, text="75")   ← 模型对滑块也只用普通的 input
    ↓
插件发现是 type=range → 直接 el.value = "75" → 派发 input/change 事件
```

模型**不需要知道**滑块要怎么拖，只需要说"把这个值设成 75"。日期框、颜色框同理。

**这就回答了你之前问的"滑块怎么办"**：

| 滑块类型 | 处理 |
|---|---|
| 原生 `<input type=range>` | `input` 动作直接赋值，不用拖 |
| 组件库的滑块（`div role=slider`），带 `aria-valuemin/max/now` | 快照里能看到这几个属性（它们在 `DEFAULT_INCLUDE_ATTRIBUTES` 里）；很多组件库支持键盘：`click` 聚焦后 `send_keys("ArrowRight")` 逐步调整 |
| 完全自绘、只认鼠标拖拽的滑块 | 坐标点击 / 截图兜底；或者绕开它（价格区间往往旁边就有输入框，或者 URL 参数能带） |
| **滑块验证码** | 不是控件问题，是反爬问题，见下文 |

## 4. 唯一的专门命令：原生 `<select>`

```python
# click 动作里
if tag_name == 'select':
    msg = f'Cannot click on <select> elements. Use dropdown_options(index={selector_index}) action instead.'
    return {'validation_error': msg}
```

然后前台（`_click_by_index`）看到这个错误，**不直接报错，而是自动帮模型调一次 `dropdown_options`**，把选项列表返回去。模型下一步直接 `select_dropdown(index, "256GB")` 就行。

为什么原生 select 要特殊对待？因为**它点开的那个菜单是操作系统画的**，不在 DOM 里，快照里看不到，点了也没有 `*[` 出现。

`dropdown_options` 其实做得更多（[default_action_watchdog.py:2824](../../browser-use/browser_use/browser/watchdogs/default_action_watchdog.py#L2824)），它会依次尝试：
1. ARIA combobox（`role=combobox` + `aria-controls` 指向一个选项列表）：如果没展开，先展开，等选项渲染出来再读；
2. 原生 `<select>`：读 `<option>`；
3. ARIA 菜单（`role=menu` / `listbox`）：读 `menuitem` / `option`；
4. Semantic UI 这类常见组件库的下拉框；
5. 目标元素本身不是下拉框，就往下找 4 层子元素。

## 5. 弹窗和验证码

**JS 原生弹窗**（`alert` / `confirm` / `prompt`）：[popups_watchdog.py](../../browser-use/browser_use/browser/watchdogs/popups_watchdog.py) 监听 CDP 的 `Page.javascriptDialogOpening`，`alert`、`confirm` 和离开页面确认 **自动点确定**，`prompt` 自动点取消（因为没法替它填内容）。然后在下一步的状态里告诉模型 `Auto-closed JavaScript dialogs: ...`，说明刚才关掉了什么。

注意 `confirm` 自动点确定，这在购物网站上是危险的：如果弹出的是"确认提交订单？"，就直接确认了。**我们要反过来：`confirm` 一律点取消**，并把内容报告给 Agent。

**页面里的弹窗**（div 做的登录框、优惠券弹层）：就是普通元素，靠 `*[` 标记 + `click` 关闭按钮 / `send_keys("Escape")`。第 4 站的"绘制顺序过滤"还会把被弹窗挡住的元素从列表里去掉，模型不会去点被挡住的东西。

**验证码**：browser-use 的云服务有代理层自动解验证码，[captcha_watchdog.py](../../browser-use/browser_use/browser/watchdogs/captcha_watchdog.py) 只是等它解完。系统提示词里写着 "CAPTCHAs are automatically solved by the browser... Do not attempt to solve CAPTCHAs manually"。

**我们不走这条路**：自动过验证码违反平台规则，也容易被封号。我们的做法是插件检测到验证码页面（URL 特征 / 页面特征），发 `captcha_detected` 事件，Agent 调 `request_human`，等你手动处理。

## 对我们插件的启示

1. **`*` 标记必须做**，成本很低：快照时把这次的 ID 集合和上次比一下。WeakMap 学号（第 2 站）让这件事变得可行。URL 变了就不标。
2. **复合控件第一版只做两种**：`<select>`（附带选项总数和前几个选项）和 `input[type=range]`（附带范围）。淘宝京东的规格选择都是 div，用不到更多。
3. **`input` 命令内部判断控件类型**：range / date / color 直接赋值，普通文本框用原生 setter + 事件。模型那边永远只有一个 `input`。
4. **`select_option` 保留**，并且 `click` 到 `<select>` 时自动返回选项列表。
5. **弹窗**：插件里可以覆盖 `window.alert/confirm`（注入到 MAIN world），或者用 `chrome.debugger` 监听对话框。**`confirm` 一律返回 false**，并把弹窗文字报告给 Go。淘宝京东很少用原生弹窗，但这个兜底要有。
6. **验证码**：只检测、不处理，交给 `request_human`。
7. **"误导比没有更糟"**：页面压缩时宁可少给信息，也不要给可能让模型误解的信息。
