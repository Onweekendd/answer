## 0. 总体比喻：给盲人朋友描述一个房间

你要通过电话给一个看不见的朋友描述一个房间，让他指挥你拿东西。

- 你**不会**说"墙上有 3721 块砖，每块砖是红色的……"（这是原始 DOM）；
- 你**不会**说柜子里、抽屉背面那些看不见的东西（不可见元素）；
- 被沙发挡住的东西你也不说，反正现在也拿不到（被遮挡的元素）；
- 你会说："左边有个**门**（能开），门上有个**把手**（不用单独说，开门就是拧把手），右边桌上有**三个按钮**，分别写着'开灯''关灯''空调'"。

页面压缩就是做这件事：**只描述看得见、能操作的东西，并且按"一个操作对象一个编号"来组织。**

## 1. 第一步：收集三份档案

browser-use 通过 CDP 同时拉三份数据（`_get_all_trees`），再按节点 ID 合并成一棵 `EnhancedDOMTreeNode` 树：

| CDP 命令 | 拿到什么 | 比喻 |
|---|---|---|
| `DOM.getDocument` | 树结构、标签名、属性、`backend_node_id`、shadow DOM、iframe 内容 | **户口本**：谁是谁、谁是谁的孩子 |
| `DOMSnapshot.captureSnapshot` | 每个节点的位置大小（bounds）、**部分**计算样式、**绘制顺序**（paint order）、滚动位置 | **体检报告**：多高多胖、站在哪、穿什么 |
| `Accessibility.getFullAXTree` | 无障碍树：角色（button/link/combobox）、名字、状态（focusable、expanded、checked、disabled） | **简历**：会干什么、现在是什么状态 |

另外还有一份补充：用 DevTools 专属的 `getEventListeners(el)` 找出**挂了 click/mousedown/pointerdown 监听器**的元素。这个只有 CDP 能用（需要 `includeCommandLineAPI`），并且页面超过 1 万个元素就跳过，太慢。

两个工程细节：

- **只取 10 个计算样式**（`REQUIRED_COMPUTED_STYLES`）：`display`、`visibility`、`opacity`、`overflow`（三个）、`cursor`、`pointer-events`、`position`、`background-color`。注释说取多了会让 Chrome 在复杂页面上崩溃。**只取你真正会用到的。**
- 三份数据**并发**请求，然后合并。

## 2. 第二步：判断"看得见"

`is_element_visible_according_to_all_parents`：

```
① CSS 隐藏：display:none / visibility:hidden / opacity:0 → 不可见
② 没有位置信息（bounds）→ 不可见
③ 在不在视口附近：
   逐层往上处理 iframe：每进一层 iframe，坐标加上 iframe 的偏移
   在每个文档里，减去滚动距离，和视口比较
   允许超出视口上下各 1000px（viewport_threshold）
```

第 ③ 点很关键：**不是只给模型看当前屏幕，而是"当前屏幕 ± 1000 像素"**。这样模型能看到马上就要滚到的内容，少滚几次；又不会把整个长页面都塞进来。快照里还会告诉模型"上面还有 1.2 页、下面还有 4.5 页"（`pages above / pages below`），它就知道要不要滚。

## 3. 第三步：判断"能操作"

`ClickableElementDetector.is_interactive`（[clickable_elements.py](../../browser-use/browser_use/dom/serializer/clickable_elements.py)）是一串**按顺序的规则**，命中就返回：

```
排除：
  非元素节点、<html>、<body>                        → 否

强信号（命中就是）：
  ① 挂了 JS click 监听器（CDP getEventListeners）      → 是
  ② 大于 100×100 的 iframe                            → 是
  ③ <label>/<span> 里两层以内包着 input/select/textarea → 是（Ant Design 的单选框就长这样）
     （<label for=xxx> 例外：它只是代理，点它等于点别人，会重复）
  ④ class / id / data-* 里有 search、magnify、glass…  → 是（搜索图标常常是个光秃秃的 div）

无障碍树（AX）属性：
  disabled 或 hidden                                  → 否
  focusable / editable / settable                     → 是
  有 checked / expanded / pressed / selected 状态      → 是
  required / autocomplete / keyshortcuts              → 是

标签：
  button input select textarea a details summary option optgroup → 是

属性：
  onclick / onmousedown / onmouseup / onkeydown / onkeyup / tabindex → 是
  role = button link menuitem option radio checkbox tab textbox
         combobox slider spinbutton search searchbox row cell gridcell → 是

AX 角色：同上，再加 listbox                            → 是

弱信号（兜底）：
  10~50px 大小、带 class/role/aria-label 等属性（像图标） → 是
  cursor: pointer                                     → 是

都没命中                                              → 否
```

比喻：**判断一个人是不是保安**。最可靠的是看工牌（JS 监听器、AX 状态）；其次看制服（button、a 标签）；再看他站的位置和姿势（role 属性）；最后实在不确定，看他手里有没有对讲机（cursor: pointer）。**信号越可靠越先判断。**

你会发现，现代前端框架（React/Vue）写的按钮经常是 `<div onClick>`，没有 `button` 标签、没有 role。这种情况靠的是 ① 监听器和最后的 `cursor: pointer`。

## 4. 第四步：五道工序把树变小

入口 `serialize_accessible_elements`（[serializer.py:114](../../browser-use/browser_use/dom/serializer/serializer.py#L114)）：

### 工序 1：建简化树（`_create_simplified_tree`）

- 直接扔掉 `<style> <script> <head> <meta> <link> <title>`；
- SVG 的子元素（`path`、`g`、`circle`……）全部扔掉，整个 SVG 只保留一行 `<svg />`；
- 带 `data-browser-use-exclude="true"` 的元素扔掉（给网站开发者留的"别看这里"开关）；
- 进入 iframe 和 shadow DOM 内部继续遍历；
- 文本节点：可见、并且去掉空白后长度 > 1 才保留；
- 给复合控件贴"铭牌"（第 3 站）。

### 工序 2：绘制顺序过滤（`PaintOrderRemover`）

比喻：**桌上叠了一摞纸**。从最上面一张开始往下看，记下"已经被盖住的区域"。如果某张纸完全落在已经被盖住的区域里，它就看不见，跳过。

```
按 paint order 从高到低（最上层先处理）：
  如果这个元素的矩形 被"已覆盖区域"完全盖住 → 标记 ignored_by_paint_order
  不管有没有被盖住：如果它"足够不透明"（背景色不是透明 且 opacity ≥ 0.8），把它的矩形并入"已覆盖区域"
  （每个 iframe 文档各算各的）
```

"只有不透明的才算覆盖"：半透明遮罩、透明背景的容器，下面的东西还是能看见的。源码里那个 0.8 后面的注释是 `this is highly vibes based number`（凭感觉定的），旁边另一行注释写的又是 0.95。**这类阈值大家都是试出来的**，我们自己做时也要留成可调的常量。

这道工序解决了一个大问题：**弹窗出现后，弹窗下面那一整页的按钮都会被过滤掉**，模型只看到弹窗里的东西，不会去点被挡住的按钮。

### 工序 3：剪枝（`_optimize_tree`）

自底向上：一个节点**既不可见、也不可滚动、也不是文本、也没有剩下的孩子**，就删掉。

比喻：剪掉枯枝。前端常见的 `div > div > div > div > span` 这种层层包装，里面的东西被删光以后，空壳也一起删掉。

### 工序 4：包含关系过滤（`_apply_bounding_box_filtering`）

比喻：**一个按钮就是一个开关**。按钮里面有个图标、有段文字、可能还有个 span 包着，但用户只需要知道"这里有个按钮"，不需要给图标和文字各发一个编号。

规则：
- "会传播"的元素：`<a>`、`<button>`、`div/span role=button`、`div/span role=combobox`；
- 它们的子元素如果 **99% 以上** 落在父元素的矩形里，就不再单独编号；
- 例外（仍然保留编号）：子元素是 `input/select/textarea/label`、子元素本身也是"会传播"的元素、有 `onclick`、有 `aria-label`、有交互类 role。

注意被排除的子元素**文字还在**，只是不给编号。模型看到的是：

```
[3502]<a />
	Apple AirPods Pro 2 USB-C
	¥1399
```

而不是给链接、标题、价格各发一个编号。

### 工序 5：分配编号 + 标记新元素

第 2 站和第 3 站讲过：编号 = `backend_node_id`，和上次快照比对打 `*`。

## 5. 最后：转成文本（`serialize_tree`）

规则：
- 用 **Tab 缩进**表示父子关系；
- 只有**可交互、可滚动、iframe** 的元素才输出成标签 `[编号]<标签 属性 />`；
- 其他元素不输出标签，只输出它们的文字（作为单独一行）；
- 属性只输出**白名单**（`DEFAULT_INCLUDE_ATTRIBUTES`）：`title type checked id name role value placeholder alt aria-label aria-expanded aria-valuemin/max/now pattern min max ...`。**注意没有 `class`**：class 名对模型基本没用，还特别长；
- 每个属性值最多 100 字符；
- 重复信息去重：属性值和文字一样就不重复输出；`<button type=button>` 里的 `type` 删掉；
- 输入框的当前值优先从 AX 树读（AX 树反映用户真正输入的值，`value` 属性可能没更新）；
- 可滚动容器加 `|SCROLL|` 前缀和滚动位置；shadow DOM 加 `|SHADOW(open)|`；
- 整段元素文本最多 **4 万字符**（`max_clickable_elements_length`），超了截断并告诉模型 "truncated"。

最终模型看到的样子（系统提示词里的例子）：

```
[33]<div />
	User form
	[35]<input type=text placeholder=Enter name />
	*[38]<button aria-label=Submit form />
		Submit
[40]<a />
	About us
```

## 6. 这套流程为什么好

回头看整个流程，它的思路是：

| 原则 | 体现 |
|---|---|
| **多信号融合**：一个来源不够准，就三个来源交叉验证 | DOM + 布局 + 无障碍树 + 事件监听器 |
| **人看不见的，模型也不用看** | 可见性、视口 ±1000px、绘制顺序遮挡 |
| **一个操作对象一个编号** | 包含关系过滤 |
| **结构保留，噪音删掉** | 剪枝、缩进、属性白名单、去掉 class |
| **宁缺毋滥** | 日期框不加误导性的子组件（第 3 站） |
| **有上限** | 属性 100 字符、总共 4 万字符 |

## 对我们插件的启示：content script 版本

| browser-use 用的 | content script 能拿到吗 | 我们的替代方案 |
|---|---|---|
| DOM 树、属性 | ✅ | 直接遍历 `document` |
| 位置大小 | ✅ | `el.getBoundingClientRect()` |
| 计算样式 | ✅ | `getComputedStyle(el)`，同样**只读需要的几个**，读多了很慢 |
| 绘制顺序 | ❌ | 用 `document.elementFromPoint(中心点)` 近似：中心点上最上面的元素不是它自己/子孙 → 被挡了 |
| 无障碍树 | ⚠️ 部分 | 读 `role`、`aria-*` 属性；`el.disabled`、`el.tabIndex >= 0`（可聚焦）、`el.isContentEditable` |
| JS 监听器 | ❌ | 只能靠 `cursor: pointer` + `onclick` 属性 + role。**React 的 onClick 是挂在根节点上的（事件委托）**，元素本身没有监听器，所以 `cursor: pointer` 反而是最实用的信号 |
| iframe 内容 | ⚠️ | manifest 里 `all_frames: true`，每个 frame 各自快照再合并；跨域 iframe 只能这样 |
| shadow DOM | ✅（open）| 遍历 `el.shadowRoot` |

### 第一版的压缩流程（建议）

```ts
function snapshot(): string {
  // ① 遍历 DOM，跳过 script/style/head/svg 子元素
  // ② 每个元素判断：
  //    visible   = 样式没隐藏 && 有尺寸 && 在视口 ±1000px 内
  //    clickable = 标签/role/onclick/tabindex/cursor:pointer（按上面的顺序）
  //    covered   = elementFromPoint(中心) 不是它或它的子孙
  // ③ 包含关系：a/button/role=button 里面的子元素不再编号，只保留文字
  // ④ 编号 = stableId(el)（第 2 站的 WeakMap），和上次比对打 *
  // ⑤ 输出：缩进 + [id]<tag 白名单属性 /> + 文字行
  //    文字截断、属性截断、总长度上限
  // ⑥ 额外：pages above/below、当前 URL、标题
}
```

### 我们独有的两条

1. **过滤个人信息区域**：登录后的用户名、收货地址、手机号所在的区域，不能发给 LLM（设计文档 5.7 节写过）。可以按选择器黑名单（页头的用户区、地址栏）+ 正则（手机号、地址格式）过滤。
2. **记录压缩前后的大小**：原始 `document.documentElement.outerHTML.length` vs 快照长度，换算成 token。这是面试时的硬数据："淘宝搜索结果页从 xxx KB 压到 xxx KB，token 降了 xx%"。

### 先从小处开始

`clickable_elements.py` 只有 246 行，**建议你先用 TS 照着它写一个 `isInteractive(el: Element): boolean`**，把 CDP 才有的信号（监听器、AX 属性）换成 content script 能拿到的。这是插件里最核心的一个函数，写完我帮你看。
