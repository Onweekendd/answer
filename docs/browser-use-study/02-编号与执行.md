## 1. 编号从哪来：用浏览器自己的"身份证号"

### 比喻：座位号 vs 身份证号

假设你是老师，要叫学生回答问题。

- **方案 A：按座位号叫**，"第 3 排第 2 个"。问题是学生一换座位，"第 3 排第 2 个"就变成别人了。
- **方案 B：按学号叫**，"2024015 号"。不管他坐哪，学号不变。

很多简单的实现（包括我上次说的方案）用的是"座位号"：每次快照从 0 开始重新编号。页面一变（懒加载插入了几个元素），所有编号都往后挪，模型手里的旧编号就指错人了。所以才需要 `snapshotId` 去检测"编号过期"。

browser-use 用的是"学号"：**直接用 CDP 的 `backend_node_id` 当编号。**

```python
def _allocate_selector_index(self, backend_node_id: int) -> int:
    """Preserve unique backend IDs and allocate a collision-free model index otherwise."""
    if backend_node_id not in self._selector_map:
        return backend_node_id        # 正常情况：编号 = 浏览器内部节点 ID
    # 极少数冲突（比如复合控件的虚拟子节点），才分配一个合成编号
    ...
```

`backend_node_id` 是 Chrome 给每个 DOM 节点分配的内部 ID，**只要这个节点还活着就不会变**。所以：

- 懒加载插入了新元素？老元素的编号不变，新元素拿到新编号；
- 模型拿着上一步的 `[12345]` 去点？只要那个元素还在，就一定点对；
- 元素被删了？查不到，返回 `Element index 12345 not available - page may have changed`。

这也是为什么你在 browser-use 的输出里看到的编号是 `[3487]`、`[3502]` 这种不连续的大数字，而不是 `[0]`、`[1]`、`[2]`。

### 编号表：`selector_map`

每次快照时，序列化器建一张表：

```python
self._selector_map[node.selector_index] = node.original_node   # 编号 → 完整节点信息
```

用 TS 类比就是 `Map<number, EnhancedDOMTreeNode>`。节点里存着 `backend_node_id`、标签名、属性、位置（bounds）、在哪个 iframe 里、无障碍树信息等。

执行动作时：

```python
node = await browser_session.get_element_by_index(params.index)   # 去缓存的 selector_map 里查
if node is None:
    return ActionResult(extracted_content='Element index ... not available - page may have changed. Try refreshing browser state.')
```

注意它查的是**上一次快照缓存的表**，不是实时去页面上找。

## 2. 执行链路：前台接单，后厨做菜

动作函数本身不直接操作浏览器，而是**发一个事件**：

```python
event = browser_session.event_bus.dispatch(ClickElementEvent(node=node))
await event
click_metadata = await event.event_result(raise_if_any=True, raise_if_none=False)
```

真正干活的是 `DefaultActionWatchdog.on_ClickElementEvent`。

比喻：**动作函数是餐厅前台**，负责听懂客人（模型）要什么、检查点单合不合理、最后把结果告诉客人；**watchdog 是后厨**，负责真正做菜。前台和后厨之间用"小票"（事件）沟通。

好处：
- 同一个"点击"事件，可以有多个监听者：一个负责点，一个负责检测下载，一个负责录屏；
- 换一种浏览器控制方式，只要换后厨，前台不用动。

在我们的架构里，Go 侧的工具函数就是"前台"，插件就是"后厨"，WebSocket 消息就是"小票"。这一层天然就分开了。

## 3. 一次点击到底做了什么

`_click_element_node_impl`（[default_action_watchdog.py:703](../../browser-use/browser_use/browser/watchdogs/default_action_watchdog.py#L703)）的步骤：

```
① 拒绝不能点的元素
   <select>      → 返回"请用 dropdown_options"
   <input type=file> → 返回"请用 upload_file"

② 如果是 checkbox/radio，先记下点击前的 checked 状态

③ 滚动到可见区域：DOM.scrollIntoViewIfNeeded，等 50ms

④ 算点击坐标
   拿元素的所有矩形（一个元素换行后可能有多个矩形）
   → 找出和视口交集面积最大的那个
   → 取它的中心点

⑤ 遮挡检查（_check_element_occlusion）
   document.elementFromPoint(x, y) 拿到这个坐标上"最上面"的元素
   如果它是目标元素、目标的子元素、或目标的父元素 → 没被挡
   否则 → 被挡了（比如有个弹窗、悬浮条盖在上面）

⑥ 没被挡：用 CDP 发真实鼠标事件
   Input.dispatchMouseEvent: mouseMoved → mousePressed → mouseReleased
   这样产生的事件 isTrusted = true，和真人点的一样

   被挡了：退回 JS 点击 this.click()

⑦ checkbox/radio：检查 checked 有没有真的变
   没变 → 再用 JS click 一次 → 再检查

⑧ CDP 点击出异常 → 也退回 JS click

⑨ 返回 {click_x, click_y}，给可观测性用
```

**这一套的核心思想是"层层兜底"**：先用最像真人的方式（CDP 鼠标事件），不行再用 JS，每一步都验证结果。

比喻：送快递。先按门铃（CDP 真实点击）；门铃被挡住了够不着，就打电话（JS click）；送完还要确认对方真的签收了（checkbox 状态检查）。

## 4. 一次输入到底做了什么

`_input_text_element_node_impl`（[default_action_watchdog.py:1759](../../browser-use/browser_use/browser/watchdogs/default_action_watchdog.py#L1759)）：

```
① 滚动到可见 → 遮挡检查 → 聚焦元素

② 特殊输入框直接赋值（_requires_direct_value_assignment）
   type=date/time/month/week/color/range
   带 datepicker 类名或 data-datepicker 属性的 jQuery/Bootstrap 日期选择器
   → 不逐字输入，直接 el.value = text，再派发事件
   原因：日期框是"年/月/日"几个小格子组成的，逐字打会乱；
         而且打到一半（"2026-1"）会触发校验，被拒绝

③ 清空原有内容（clear=True 时）

④ 逐字输入，每个字符三个 CDP 事件：
   keyDown（不带文字）→ char（带文字）→ keyUp
   字符之间有小延迟，模拟真人打字速度
   换行符当成 Enter 键处理

⑤ contenteditable（富文本编辑器）有个坑：第一个字符可能被吞掉
   → 打完第一个字检查一下，丢了就补打

⑥ 派发框架事件（_trigger_framework_events）
   input（InputEvent，inputType='insertText'）→ change → blur
   让 React 受控组件、Vue v-model、Angular 都感知到值变了

⑦ 读回实际值，和要输入的不一样就在结果里提示（第 1 站讲过）
```

第 ⑥ 步你应该很熟：**React 受控组件只认 `input` 事件**，直接改 `el.value` 不派发事件，React 的 state 不会更新，下次重新渲染又把值改回去了。

## 5. 编号过期了怎么办

即使用了"学号"，还是有过期的情况：元素被删掉重建了（比如 React 重新渲染了整个列表，节点换了一批）。browser-use 的处理很简单：

- 查不到 → 返回"page may have changed. Try refreshing browser state."
- **下一步开始时本来就会重新拍快照**，模型自然会看到新编号。

另外第 5 站会讲 `multi_act`：一步里有多个动作时，只要 URL 变了，后面的动作就不执行，从源头上避免拿旧编号操作新页面。

## 对我们插件的启示

### 编号：用 WeakMap 模拟 `backend_node_id`

content script 拿不到 `backend_node_id`，但可以自己造一个"学号"：

```ts
// content script 里，常驻
const idOf = new WeakMap<Element, number>()   // 元素 → 学号
const byId = new Map<number, WeakRef<Element>>() // 学号 → 元素（反查用）
let nextId = 1

function stableId(el: Element): number {
  let id = idOf.get(el)
  if (id === undefined) {
    id = nextId++
    idOf.set(el, id)
    byId.set(id, new WeakRef(el))
  }
  return id
}

function findById(id: number): Element | null {
  const el = byId.get(id)?.deref()
  return el && el.isConnected ? el : null   // 被 GC 或已从 DOM 移除，都算找不到
}
```

- `WeakMap` 的 key 是元素本身，元素被删除、被回收后，条目自动消失，不会内存泄漏；
- 同一个元素在多次快照里拿到同一个编号，和 `backend_node_id` 效果一样；
- `isConnected` 检查元素还在不在文档里。

**注意**：页面跳转后 content script 会重新注入，表是空的，编号从 1 重新开始。这没关系，因为跳转后本来就要重新快照。

### 点击：同样层层兜底

| browser-use（CDP） | 我们的插件 |
|---|---|
| `DOM.scrollIntoViewIfNeeded` | `el.scrollIntoView({ block: 'center' })` |
| 取最大可见矩形的中心 | `el.getClientRects()` 同样算 |
| `elementFromPoint` 遮挡检查 | **完全一样**，content script 就能调 |
| `Input.dispatchMouseEvent`（isTrusted=true） | 默认用 `el.click()`（isTrusted=false）；需要可信事件时走 `chrome.debugger` + 同样的 CDP 命令 |
| checkbox 点击后验证 | 一样 |

第一版建议：**先只用 `el.click()` + 遮挡检查**。等真的遇到"网站忽略不可信事件"再接 `chrome.debugger`（会在浏览器顶部显示"正在调试此浏览器"的提示条）。

### 输入：照抄步骤 ②⑥⑦

React 受控输入框的标准写法：

```ts
function setNativeValue(el: HTMLInputElement, value: string) {
  // 用原型上的 setter，绕过 React 对实例 value 属性的劫持
  const setter = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value')!.set!
  setter.call(el, value)
  el.dispatchEvent(new InputEvent('input', { bubbles: true, inputType: 'insertText', data: value }))
  el.dispatchEvent(new Event('change', { bubbles: true }))
}
```

然后读回 `el.value` 对比，不一致就在结果里提示。逐字模拟键盘（步骤 ④）第一版可以不做，淘宝京东的搜索框直接赋值 + 事件就够了。
