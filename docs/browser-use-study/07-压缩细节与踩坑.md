## 起因：我们第一版快照的数据

在淘宝首页（未登录）跑了一次 `__buyOrNot.snapshot(8000)`：

| 指标 | 数值 |
|---|---|
| 输出 | 7846 字，93 行，被截断 |
| **链接（href）占的字符** | **6402 字，占 81.6%** |
| 其余（标签 + 文字） | 1444 字 |

最典型的一行：

```
[20]<a href=https://s.taobao.com/search?q=%E6%96%B0%E5%9E%8B%E5%B1%8B%E9%A1%B6%E5%BD%A9%E9%92%A2%E7%93%A6&ie=utf8&tab=all&>新型屋顶彩钢瓦
```

一个汉字经过 URL 编码变成 9 个字符（`%E6%96%B0` 就是"新"）。这一行 130 个字符里，有用的信息只有"搜索：新型屋顶彩钢瓦"。

带着这个问题去看 browser-use 怎么做。

## 1. 最大的发现：交互元素列表里根本没有 href

属性白名单 `DEFAULT_INCLUDE_ATTRIBUTES`（[views.py:18](../../browser-use/browser_use/dom/views.py#L18)）里有 `title`、`type`、`placeholder`、`aria-label`、`value` 等几十个属性，**没有 `href`**，`class` 也被注释掉了。

（同一个文件里另一个列表 `STATIC_ATTRIBUTES` 包含 `href`，但它的用途是给元素算哈希、判断"两次快照里是不是同一个元素"，不会发给模型。）

也就是说，模型每一步看到的页面是这样的：

```
[3502]<a />
	Apple AirPods Pro 2 USB-C
	¥1399
```

只知道"这里有个链接，写着什么"，不知道它指向哪里。

**那模型要链接时怎么办？** 有三条路：

| 方式 | 做法 | 成本 |
|---|---|---|
| 直接点 | `click(3502)` | 一次动作 |
| `find_elements` | 按 CSS 选择器查元素，`attributes=["href"]` 只取需要的属性（[tools/service.py:1345](../../browser-use/browser_use/tools/service.py#L1345)） | 不调用 LLM |
| `extract` | 整页转成 markdown（`extract_links=True` 才保留链接），交给**另一个 LLM** 按问题或 JSON schema 提取，主 Agent 只看到提取结果（[tools/service.py:1068](../../browser-use/browser_use/tools/service.py#L1068)） | 多一次小模型调用 |

**比喻**：交互元素列表是一张**遥控器按键图**，只告诉你"有哪些键、键上写着什么"；页面的具体内容放在**资料室**里，要查资料就派一个助手（小模型）进去，按你的问题把答案带出来。按键图要每一步都看，所以必须小；资料室偶尔才进，可以大。

这和我们设计文档 5.5 节的结论是同一个思路："主 Agent 的 LLM 永远看不到原始页面，只看到工具返回的结构化结果。"

## 2. 真要放 URL 时：统一缩短，用完再还原

即使交互列表不放 href，URL 还是会出现在别的地方：当前页面地址、标签页列表、`extract` 的结果。它们在发给模型之前统一做了一次缩短（[agent/service.py:1793](../../browser-use/browser_use/agent/service.py#L1793)，2025-09-05 加入，提交 `b5aebf0b0` "shorten super long URLs"）。

规则：

```
1. 从第一个 ? 或 # 处把 URL 切成两段：base（协议 + 域名 + 路径）和 after_path（查询参数 + 锚点）
2. after_path ≤ 25 个字符：不动
3. 否则：base + after_path 的前 25 个字符 + "..." + after_path 的 md5 前 7 位
4. 只有缩短后真的更短才替换，并记下 {短 URL: 原 URL}
```

然后是关键的另一半：**模型的回复里如果用到了短 URL，再把它换回原 URL**（[agent/service.py:1870-1931](../../browser-use/browser_use/agent/service.py#L1870-L1931)，递归处理动作参数里的每一个字符串）。

```
发给模型之前：所有消息里的长 URL  →  短 URL，记下映射表
模型回复：     navigate(url="https://item.taobao.com/item.htm?id=1234...a1b2c3d")
执行动作之前： 短 URL  →  原 URL
```

为什么要这样做，而不是直接截断？

- **省 token**：查询参数通常是跟踪参数，对模型没用。
- **防抄错**：让模型逐字复制一个 300 字符的 URL，它很容易抄错一两个字符，跳到一个错误的页面。短 URL 加映射表，模型只要抄对几十个字符。
- **md5 后缀保证唯一**：两个前缀相同、参数不同的 URL 不会被缩成同一个。

**他们没做、我们要做的一步**：这套规则不解码。对英文网站问题不大，但淘宝的中文参数编码后会膨胀 9 倍，前 25 个字符只装得下不到 3 个汉字。我们应该先 `decodeURIComponent` 再处理。

## 3. 属性：白名单、去重、截断

`_build_attributes_string`（[serializer.py:1204](../../browser-use/browser_use/dom/serializer/serializer.py#L1204)）一个元素一个元素地拼属性，规则很细：

| 规则 | 例子 | 为什么 |
|---|---|---|
| 只取白名单里的属性 | 没有 `class`、`style`、`href` | class 名长、对模型几乎没用 |
| 每个属性值最多 100 字符 | 超出部分变成 `...` | 防止一个属性吃掉预算 |
| 多个属性值相同，只留第一个 | `title` 和 `name` 都是 "search" | 重复的信息不说两遍 |
| `aria-label` / `placeholder` / `title` 和元素文字一样，就删掉 | `<button aria-label=搜索>搜索` → `<button>搜索` | 同上 |
| `<button type=button>` 删掉 `type` | | 信息量为零 |
| `required=false`、`invalid=false` 删掉 | | 只在为真时才有意义 |
| **密码框的值永远不输出** | | 见第 6 节，2026-03 修的 |
| 输入框的值从无障碍树读 | | 用户输入后，DOM 上的 `value` 属性不会更新 |

最后一条对我们的意义：content script 里读输入框，要用 `el.value`（属性，property），不要用 `el.getAttribute('value')`（特性，attribute）。后者是页面初始的值，用户输入以后不会变。

## 4. 图片：只留文件名

问题：很多可点击的元素里只有一张图，没有文字（商品卡片的图片链接、图标按钮）。模型看到的就是一个空的 `[201]<a />`，不知道它是什么。

2026-08 的修复（`96117ef8f` "expose image context for clickable elements"）：给这种元素附上子孙图片的信息（[serializer.py:931](../../browser-use/browser_use/dom/serializer/serializer.py#L931)）：

```
[201]<a image_alt=... image_src=acme-bank-primary-card.png />
```

处理图片地址的规则：

- 去掉查询参数和锚点，**只留最后一段文件名**；
- `data:` 开头的（内嵌的 base64 图片）直接丢掉；
- 属性值超过 4096 字符的直接跳过；
- 最多取 3 张图，最多往下找 100 个子孙节点（这个上限是三天后的另一个修复 `1cddc7a79` "make image traversal allocation bounded" 补上的：一开始没有上限，大页面上会遍历太多节点）。

对我们来说，**淘宝商品图的 `alt` 往往就是商品标题**，比文件名有用得多。

## 5. 总量和"页面状态"

**总长度上限**：交互元素文本最多 4 万字符，超了直接截断，并在标题里写上 `Interactive elements (truncated to 40000 characters)`（[prompts.py:254](../../browser-use/browser_use/agent/prompts.py#L254)）。截断方式很朴素：直接切字符串。

除了元素列表，每一步还会告诉模型几件事（[prompts.py:223-335](../../browser-use/browser_use/agent/prompts.py#L223-L335)）：

| 信息 | 例子 | 作用 |
|---|---|---|
| 页面统计 | `52 links, 31 interactive, 0 iframes, 12 images, 640 total elements` | 让模型对页面规模有个概念 |
| 空页面提示 | 元素少于 10 个 → `Page appears empty - consider waiting` | 页面还没加载出来，别急着操作 |
| **骨架屏提示** | 还有网络请求没完成，并且文字字数 < 元素数 × 5 → `page may still be loading` | 很多页面先渲染一个灰色占位框架，内容稍后才填进来 |
| 滚动位置 | `1.2 pages above, 4.5 pages below — scroll down to reveal more content` | 告诉模型下面还有内容 |
| 首尾标记 | `[Start of page]` / `[End of page]` | 模型知道自己看到了页面的开头或结尾 |
| 标签页列表 | `Tab a1b2: https://... - 标题前 30 字` | 标签页 id 只显示后 4 位 |

"骨架屏"这一条对淘宝很重要：淘宝搜索页的商品是异步加载的，`document_idle` 时商品列表可能还是空的占位框。

## 6. 他们踩过的坑（按时间）

这些都是 git 历史里实际的修复提交。每一条都值得记住，因为我们大概率也会遇到。

### 坑 1：过滤掉的东西，要告诉模型"这里有东西被过滤了"

**2026-01-25，`eb8e1c1d5`**：视口上下 1000 像素以外的 iframe 内容被过滤掉了，模型完全不知道它们存在，只能"盲滚"去找。修复：在快照里加提示，告诉模型"这里还有隐藏的内容，大约在下面几屏的位置"。

**教训**：压缩是在**丢信息**。丢的时候要留一句"这里丢了什么"，否则模型会以为页面上就只有这些。我们的 `truncated: true`、`pages below` 都是这一类。

### 坑 2：看起来显然的噪音规则，可能删掉真正的目标

**2025-11-12，`839c1412e`**：在"判断可交互"里加了一条规则，跳过带 `inert` 或 `aria-hidden="true"` 的元素，目的是过滤轮播图里那些看不见的幻灯片。**三天后被整个撤回了**（`fb8994de1`），撤回的提交没写原因。

我的推测（源码里没有说明）：`aria-hidden` 的意思只是"对读屏软件隐藏"，不代表看不见、点不了。很多网站给装饰性的图标、甚至可以点的按钮都加了 `aria-hidden`，一刀切会把它们一起删掉。

**教训**：我们首页快照里的轮播翻页按钮 `[88]~[92]`（"1 2 3 4 5"）看起来是噪音，但不要用一条"显然"的规则去删。噪音规则要在真实页面上验证，看删掉的是不是真的都是噪音。

### 坑 3：密码的值进了快照

**2026-03-17，`e8d1681cd`** "strip password field values from DOM snapshots sent to LLM"：密码输入框的值会被当作普通属性发给模型。注释里写了危险在哪：网页内容里的提示注入可以诱导模型把它发出去。

**教训**：快照是要发给第三方 LLM 的，**发出去之前要过一遍隐私过滤**。我们的版本是：用户名、收货地址、手机号（设计文档 5.7 节）。

### 坑 4：大页面把自己拖死

**2026-04-01，`5ec5c8d43`**：两个性能问题。

1. 构建 DOM 树时，每个节点都调用一次异步操作。在 10 万个元素的页面上就是 10 万次。
2. 遮挡计算里的"已覆盖区域"是一组矩形。每加一个新矩形，最多会切成 4 个。半透明图层很多时，矩形数量指数级膨胀，内存和 CPU 一起爆掉。修复：最多 5000 个矩形（`_MAX_RECTS`）。

同时补了一套压力测试：15 个页面，最多 13.2 万个元素。

**教训**：**每一个"循环"和"集合"都要有硬上限**。我们的 `snapshot` 跑在页面的渲染进程里，它卡住就是页面卡住。淘宝搜索页的元素很多，要限制最多处理多少个元素、最多花多少毫秒。

### 坑 5：清理文本的正则写得太贪，把 URL 毁了

**2026-07-06，`ab08dea62`**，两个 bug：

1. 有一个清理用的正则，会删掉所有 `%XX` 形式的字符序列。结果**所有百分号编码的 URL 都被破坏了**，而且偏偏是在用户要求 `extract_links=True` 的时候。
2. 另一个规则想删掉 SPA 页面里嵌入的大段 JSON：一行超过 100 字符、并且以 `{` 或 `[` 开头，就删掉。结果把 markdown 链接 `[文字](很长的链接)` 也删了，因为它也以 `[` 开头。

修复：删掉那个 `%XX` 正则；判断 JSON 时**真的用 `json.loads` 解析一下**，能解析才删（[markdown_extractor.py:179](../../browser-use/browser_use/dom/markdown_extractor.py#L179)）。同时把 HTML 转 markdown 抽成纯函数，方便写单元测试。

**教训**：

- 淘宝的 URL 里全是 `%XX`。我们压缩 URL 时，**要么用 `decodeURIComponent` 正确解码，要么原样保留，不要用正则去"清理"**。
- `decodeURIComponent` 遇到不合法的 `%` 序列会抛 `URIError`，要包在 try/catch 里，失败就用原文。
- 判断"这是不是 X"，**用真正的解析器，不要只看前缀**。

### 坑 6：一个过滤器，只在一条输出路径上生效

**2026-07-15，`c84149c27`**：遮挡计算已经正确算出"弹窗下面的那些元素被盖住了"，但这个标记只在**分配编号**时用到。**输出文字**时没有检查它，所以被弹窗盖住的文字照样发给了模型。模型看到一堆实际上看不见的内容，会被误导。

**教训**：一个"不该给模型看"的判断，要在**所有**输出的地方都生效。我们以后加隐私过滤时也一样：编号元素、纯文字、图片 alt、标题，每一处都要过滤。

## 7. `extract` 那条路的细节

`extract` 是第 1 节表格里的第三条路。它的实现（[markdown_extractor.py](../../browser-use/browser_use/dom/markdown_extractor.py)）里有几个对我们有用的做法：

1. **先去掉非内容标签**：`style`、`script`、`head`、`meta`、`link`、`title`，以及隐藏的 `<code>`（SPA 常把页面状态 JSON 藏在里面）。
2. **转成 markdown**：表格、列表、标题的结构都保留下来，比纯文本好读。
3. **清理**：删掉大段 JSON；连续 4 个以上的换行压成 3 个；删掉空行。
4. **按结构分块，而不是按字符硬切**：每块最多 10 万字符，但不会从表格、代码块、列表项的中间切开；表格跨块时，下一块开头会重复一遍表头。
5. **能续读**：被截断时告诉模型 `use start_from_char=12345 to continue`，下次从这里接着读。
6. **翻页去重**：参数 `already_collected` 传入已经收集过的商品名或 URL，提取时跳过它们。**这正是搜索结果翻页时要用的。**
7. **把压缩统计告诉模型**：格式是 `Content processed: <N> HTML chars → <N> initial markdown → <N> filtered markdown`（[tools/service.py:1151](../../browser-use/browser_use/tools/service.py#L1151)）。

这也是我们设计文档里 `search_products` 的实现方式：插件给出压缩后的页面 → Go 交给小模型按 schema 提取 → 主 Agent 只拿到商品列表。

```
		iPhone
		17
		手机  A19 芯片 正品新款 5G手机 全新 支持淘金币 国补
		28万+数码3c爱好者看过
		...
		5499
		[8588]<div />
		国补后
		3000+人付款

```

从这份真实输出能看到：

1. **没有 href，但商品 id 还在**：淘宝在卡片上写了 `id=item_id_980696242744`，`id` 在属性白名单里，模型能拿到商品 id，不需要链接。
2. **href 的问题解决了，`image_src` 又把它带回来了**：第 4 节的"图片上下文"功能在淘宝上占掉一半预算，而 `O1CN0161oVIam3...` 这种 CDN 文件名对模型没有任何意义。同一组图片还在外层 `div` 和内层 `a` 上**各重复了一遍**。这说明：**一条在英文网站上合理的规则，到了别的网站可能完全相反**。
3. **价格没有货币符号，和标签分开**：`5499` 单独一行，下一行是"国补后"。模型要自己猜这是国补后的价格还是原价。
4. **标题被拆成多行**：`Apple/苹果`、`iPhone`、`17` 各占一行，因为它们在页面上是不同的文字节点。
5. **懒加载**：最后几个卡片只有 `<a id=item_id_... />` 加一个空 `div`，内容还没加载，要滚动以后才有。
6. **账号昵称被发给了模型**：第 2 步（淘宝首页）页头里的账号昵称作为一个普通链接出现在快照里。browser-use 只过滤了密码框，没有过滤这类个人信息。我们要在插件里自己做（坑 3）。

## 8. 对我们的淘宝快照：下一版怎么改

按收益从大到小：

### ① 交互列表里不放完整的 href（预计收益最大）

首页数据里，标签加文字一共只有 1444 字。去掉 href 后，同样 8000 字的预算能装下大约 5 倍的元素。

但我们和 browser-use 有一点不同：设计文档里的 `get_product_detail(url)` 需要商品链接。折中方案：

| 链接类型 | 处理 |
|---|---|
| 商品详情（`item.taobao.com`、`detail.tmall.com`、`item.jd.com`） | 只保留商品 id，例如 `item=6789012345` |
| 搜索链接（`s.taobao.com/search?q=`） | 解码出搜索词，例如 `search=新型屋顶彩钢瓦` |
| 其他 | 不输出 href |

更进一步，可以完全不让 URL 进入模型：工具参数用**元素编号**，例如 `open_product(12)`，由 Go 去问插件"12 号元素的链接是什么"。这样连"抄错 URL"的问题都不存在。

### ② 加上页面状态

模仿第 5 节：元素统计、`pages above / below`、`[Start of page]` / `[End of page]`、骨架屏提示。

### ③ 图片：只用 `alt`，不要文件名

只有图片、没有文字的链接，用图片的 `alt` 补上文字。**不要输出图片地址或文件名**：7.5 节的实测里，淘宝的 CDN 文件名占掉了 browser-use 一半的预算，却没有任何信息量。

### ③-b 商品 id 用 `id=item_id_…` 就够

实测里淘宝在商品卡片上写了 `id=item_id_980696242744`，直接读它比解析 href 更简单、更稳。

### ④ 处处设上限

最多处理多少个元素、最多花多少毫秒、每个属性最多多少字。

### ⑤ 用真实页面做测试样本

把真实的快照保存下来作为测试样本（先删掉个人信息），每次改规则都对比一下前后的输出。browser-use 修坑 5 时做的第一件事，就是把转换逻辑抽成纯函数、补上单元测试。我们的 `describe`、`clip`，以及接下来的链接压缩函数，都可以照这样写。

### 先不做的

- **噪音过滤**（导航栏、轮播、广告）：等在登录状态下看过搜索结果页的数据再说。坑 2 提醒我们，凭感觉写的过滤规则容易误删。
- **长 URL 映射表**：如果走"工具参数用元素编号"这条路，就不需要它了。
