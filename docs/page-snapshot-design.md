# 页面快照压缩方案

> 插件把电商页面压缩成文本交给 Go 的方案。背景和依据见 [browser-use 学习笔记第 4 站](browser-use-study/04-页面压缩.md)、[第 7 站](browser-use-study/07-压缩细节与踩坑.md)，以及 [设计文档 5.7 节](buy-or-not-design.md#57-页面压缩效果好坏的关键)。

---

## 1. 从数据出发

| 来源 | 页面 | 结果 | 主要问题 |
|---|---|---|---|
| 我们第一版 `snapshot` | 淘宝首页（未登录） | 7846 字，93 个元素，被截断 | href 占 **81.6%**；中文 URL 编码膨胀 9 倍 |
| browser-use | 淘宝搜索页（登录） | 约 2.4 万字，277 个编号元素，40 个商品 | 图片文件名占 **47.7%**；标题拆成多行；价格和"国补后"分开；昵称被发给模型 |

两个结论：

1. **最大的浪费都来自"对模型没意义的长字符串"**：URL、CDN 文件名。先砍掉它们，收益最大，风险最小。
2. **按"一个可操作对象一行"组织，比按 DOM 节点组织更紧凑**：一个链接里的标题、价格、店铺本来就是一个整体。

**目标**：淘宝搜索页（只是拿来测量的样本页面）的 40 个商品，交互模式下压到 8000 字以内，并且每个商品的标题、价格、店铺在同一行。这是目标，要实测验证。

**约束：插件是通用插件，不针对任何具体网站写规则。** 每条规则都要问一句"换一个网站还成立吗"。淘宝、京东只是测量用的样本页面。

## 2. 两种模式：按键图和资料室

browser-use 最重要的做法是把"能点什么"和"页面上有什么"分开（第 7 站第 1 节）。我们也分成两个命令：

| | `snapshot`：交互模式 | `read`：内容模式 |
|---|---|---|
| 给谁看 | 主 Agent（用底层原语时） | 负责提取的小模型（领域工具内部） |
| 回答什么 | 页面上能点什么、能输入什么 | 页面上有哪些商品、价格、评价 |
| 组织方式 | 编号元素，一个可操作对象一行 | 内容块，一个商品一块 |
| 预算 | 8000 字 | 3 万字，超出分块续读 |
| 调用频率 | 每一步 | 每个领域工具一次 |

一次 DOM 遍历，产出一棵中间结构，两种模式只是**最后的输出格式**不同。前面的可见性、隐私过滤都共用。

```
DOM ──① 遍历──② 可见──③ 可交互──④ 遮挡──⑤ 合并──⑥ 隐私──┬─▶ ⑦a snapshot 文本（编号）
                                                          └─▶ ⑦b read 文本（内容块）
```

## 3. 流水线

每一道工序都写明：做什么、规则、上限、出处。

### ① 遍历

- 用 `TreeWalker` 从 `document.body` 开始，进入 open shadow root（`el.shadowRoot`）。
- 直接跳过整棵子树：`script`、`style`、`noscript`、`template`、`head`、`svg` 的内部（`svg` 本身保留一行）。
- iframe 第一版不进入，只在统计里计数。
- **硬上限**（第 7 站坑 4）：最多访问 2 万个节点、最多 50 毫秒。超过就停，结果里标记 `partial: true`。

### ② 可见

按代价从低到高判断，前面的不通过就不再算后面的：

1. `getBoundingClientRect()` 宽或高为 0 → 不可见；
2. 在不在**视口上下各一屏**以内（browser-use 是 ±1000px）。范围外的不输出，但计入"上面还有 x 屏、下面还有 y 屏"；
3. `getComputedStyle`：`display: none`、`visibility: hidden`、`opacity: 0` → 不可见。**只读这几个属性**，计算样式很贵（第 4 站）。

**不用** `aria-hidden` 判断可见性（第 7 站坑 2：browser-use 加了又撤回）。

### ③ 可交互

照第 4 站的规则，换成 content script 能拿到的信号，**按可靠程度排序，命中即返回**：

1. 排除：`disabled`、`inert`；
2. 标签：`a[href]`、`button`、`input`（非 hidden）、`select`、`textarea`、`summary`；
3. `role`：`button`、`link`、`checkbox`、`radio`、`tab`、`menuitem`、`option`、`combobox`、`textbox`、`switch`；
4. 属性：`onclick`、`tabindex >= 0`、`contenteditable`；
5. 兜底：`cursor: pointer`，**并且父元素不是 pointer**。cursor 会继承，不加这个条件，一个按钮里的所有子元素都会被当成可点的。

React 的 `onClick` 挂在根节点上（事件委托），元素本身看不到监听器，所以第 5 条在现代网站上很重要。

### ④ 遮挡

对**视口内**的可交互元素，用 `document.elementFromPoint(中心点)` 检查：拿到的元素既不是它自己、也不是它的子孙 → 被挡住了，不编号。

这是 browser-use"绘制顺序过滤"的近似版。`elementFromPoint` 只对视口内的坐标有效，视口外的元素跳过这一步。被挡住的元素，**文字也不输出**（第 7 站坑 6：过滤要在所有输出路径上生效）。

### ⑤ 合并：一个可操作对象一行

browser-use 的"包含关系过滤"：`a`、`button`、`role=button` 里面的子元素不单独编号，**它们的文字并入父元素**。

我们再进一步：**把父元素内所有文字节点拼成一行**，用空格连接。这样标题碎片 `Apple/苹果`、`iPhone`、`17` 会重新拼回一句话，价格和"国补后"也会挨在一起。

例外（仍然单独编号）：子元素是 `input`、`select`、`textarea`，或者自身也是 `a`/`button`（比如卡片里的店铺链接）。

### ⑥ 隐私过滤：唯一的出口

**所有文字在输出前都经过同一个函数**，不在各处分别过滤（第 7 站坑 6）。

- **正则打码**：手机号、身份证号、邮箱这类"看格式就能认出来"的，替换成 `[手机号]` 等。
- **用户自己填的词表**：账号昵称、真实姓名、地址这类看格式认不出来的，在插件 popup 里填一组要隐藏的词，出现就替换成 `[已隐藏]`。这是通用做法，不需要认识任何网站的页面结构。
- **输入框**：`type=password` 的值永远不输出（browser-use 2026-03 的修复）；其他输入框的值读 `el.value`（属性），不读 `getAttribute('value')`。

browser-use 在实测里把账号昵称发给了模型（第 7 站 7.5 节），这一步不能省。

### ⑦a 输出：`snapshot`

```
url: s.taobao.com/search?q=iphone17
title: iphone17_淘宝搜索
stats: 2554 elements, 61 interactive, 45 links, 0.0 pages above, 1.4 pages below
[Start of page]
[0]<input name=q placeholder=请输入搜索文字 value=iphone17>
[1]<button>搜索
[5]<a id=item_id_980696242744>【晒单返100元】Apple/苹果 iPhone 17 手机 A19 芯片 正品新款 5G手机 全新… 5499 国补后 3000+人付款 天猫校园教育官方旗舰店
...
(truncated: 23 more elements below)
```

`id=item_id_…` 不是我们针对淘宝写的规则：`id` 在通用的属性白名单里，淘宝自己在卡片上写了这个 id，它就自然出现了。换一个网站，出现的就是那个网站自己写的 id。

规则：

| 项 | 规则 | 依据 |
|---|---|---|
| 头部 | URL（解码后去掉跟踪参数）、标题、统计、滚动位置 | 第 7 站第 5 节 |
| 首尾标记 | `[Start of page]` / `[End of page]` | 同上 |
| 属性白名单 | `id`、`type`、`name`、`placeholder`、`aria-label`、`title`、`value`、`checked`、`selected`、`expanded`、`disabled`；`role` 只在和标签不一致时输出 | 第 7 站第 3 节 |
| 去重 | 属性值和文字相同就不输出属性；`button type=button` 的 type 不输出 | 同上 |
| 链接 | **一律不输出 href**。模型用编号操作元素，不需要地址。真要地址时，Go 用 `link(编号)` 命令单独取（见第 5 节） | 第 7 站第 1 节 |
| 页面地址 | 头部的当前网址解码后显示（中文还原），超过 100 字截断 | 首页实测：中文编码后膨胀 9 倍 |
| 图片 | 只有图片没有文字的元素，用图片的 `alt` 当文字。**不输出图片地址和文件名** | 7.5 节：文件名占 47.7% |
| 每个元素的文字 | 最多 120 字，超出加 `…` | 卡片文字较长，比普通按钮宽松 |
| 属性值 | 最多 60 字 | |
| 总长度 | 默认 8000 字。按 DOM 顺序输出，满了就停，并说明还剩多少个没输出 | 坑 1：丢了什么要说出来 |
| 编号 | 本次快照内从 0 开始连续编号，编号 = `elements` 数组下标 | 已实现 |
| 状态文字 | 除了可交互元素，再输出少量**说明页面状态的文字**，不带编号：标题（`h1`~`h3`）、弹窗和提示（`dialog`、`role=dialog`、`role=alert`、`role=status`）、表单旁的 `label`。和可交互元素一起按页面顺序排列，计入总预算 | 2026-10-15 决定。只看按钮，模型看不懂"请先选择规格""已下架""确定要离开吗"这类状态；browser-use 的交互列表里也带文字（第 4 站第 5 节） |

状态文字的样子：

```
# Apple iPhone 17 256GB
[0]<button>加入购物车
! 请先选择规格
```

这几类都是通用的 HTML 语义和 ARIA 角色，不针对任何网站。要处理的重复问题：在可交互元素**里面**的标题（比如商品卡片 `<a>` 里的 `<h3>`），文字已经在那一行里了，不再单独输出；弹窗本身包含按钮，弹窗那一行只输出按钮以外的说明文字。

**URL 解码**一律用 `decodeURIComponent`，包在 try/catch 里，失败就保留原文。**不用正则清理 `%XX`**（第 7 站坑 5：browser-use 就是这样把 URL 毁掉的）。

### ⑦b 输出：`read`

```
url: s.taobao.com/search?q=iphone17

【晒单返100元】Apple/苹果 iPhone 17 手机 A19 芯片 正品新款 5G手机 全新 支持淘金币 国补 28万+数码3c爱好者看过 Apple/苹果 120Hz 6.3英寸 5499 国补后 3000+人付款 浙江 杭州 国家补贴15% 超级爆款 明日达 品牌授权 天猫校园教育官方旗舰店

【3期免息/国家补贴15%】Apple/苹果 iPhone 17 手机 A19 芯片 2025 新款 …
...
```

- **按块输出，块的划分用通用规则**：块级元素（`p`、`li`、`section`、`article`、`h1`~`h6`、`tr` 等）各成一块；一个链接或按钮的全部文字成一块（和 ⑤ 合并是同一个规则）。商品卡片在 HTML 里本来就是一个链接或一个 `li`，不需要认识网站也能分开。
- 标题 `h1`~`h6` 输出成 markdown 的 `#`，表格输出成 markdown 表格，结构交给模型自己理解。
- 不编号、不输出交互元素。它的读者是提取用的小模型，不需要点击。
- 超过 3 万字就分块，告诉 Go "还有下一块，从第 N 个字符继续"（browser-use 的 `start_from_char`）。

Go 拿到以后交给小模型，按任务给出的 JSON schema 提取，比如 `[{title, price, priceLabel, shop, sales}]`。"页面上有什么字段"由 schema 决定，插件不需要知道。

## 4. 通用内核 + 站点策略

**内核只用通用规则**，不写任何域名判断和站点选择器。换一个网站，内核不用改。

| 需求 | 内核的通用做法 |
|---|---|
| 链接 | 不输出 href；`id` 在通用属性白名单里，网站自己写了有意义的 id 就会出现 |
| 分块 | 一个链接 / 一个块级元素就是一块 |
| 隐藏账号昵称 | 用户在 popup 里填要隐藏的词 |
| 过滤导航、广告 | 以后用通用信号（`nav`、`header`、`footer`、`aside` 和对应的 ARIA 角色），先在多个网站上验证（第 7 站坑 2） |

**通用规则不够精确的地方，用站点策略增强。** 策略是仓库里的内置代码，放在单独的目录，通过策略表接入内核：

```
extension/src/
  snapshot/          通用内核
  strategies/
    types.ts         SiteStrategy 接口
    index.ts         策略表 + pick(url)
    taobao.ts        每个网站一个文件
```

```ts
// 每个钩子都是可选的，不实现就走通用逻辑
export interface SiteStrategy {
  name: string;
  matches(url: URL): boolean;
  skip?(el: Element): boolean;          // 遍历时跳过这棵子树（噪音、账号区）
  extraAttrs?(el: Element): string[];   // snapshot：给元素补充属性，比如 item=<id>
  blocks?(doc: Document): Element[];    // read：怎么分块，比如按商品卡片
  fields?(block: Element): Record<string, string> | undefined; // read：块内直接取结构化字段
}
```

规矩：

1. **内核只 import 策略表**（`strategies/index.ts`），不直接 import 某个网站的策略。以后用 ESLint 的 `no-restricted-imports` 检查。
2. **策略只能增强。** 没匹配到就走通用逻辑；钩子抛异常就当它不存在，退回通用逻辑；选择器一个都没选中也退回。这些情况都记进 `stats`（`strategy: taobao, error: …` / `matched: 0`），让 Go 能发现策略坏了。
3. **先有数据再加策略。** 加之前在那个网站上量一次通用版，确认有一个通用规则解决不了的具体问题；加之后再量一次，两次的 `stats` 都记进第 9 节。

可能的第一批策略（都要等实测确认）：淘宝页头账号区的 `skip`；商品链接的 `extraAttrs`（`item=<id>`）；商品卡片的 `blocks` 和价格的 `fields`。

## 5. 和 Go 的协议变化

| 变化 | 原因 |
|---|---|
| `snapshot` 结果增加 `snapshotId` 和 `stats` | 见下 |
| `click` / `type` 的参数增加 `snapshotId` | 编号只在那一次快照里有效。content script 发现 id 对不上，返回 `STALE_SNAPSHOT` 错误，让 Agent 重新快照，而不是点错元素 |
| 新增命令 `read` | 内容模式 |
| 新增命令 `link(编号)` | 快照里没有 href。Go 真需要某个链接的地址时（比如要在同一个标签页里打开它，而不是点击后新开一个），用这个命令单独取。地址只给 Go，不一定给模型 |
| `stats` 里带上压缩前后的大小和耗时 | 原始 `document.documentElement.outerHTML.length`、输出长度、遍历节点数、毫秒数。用于调优，也是面试时的硬数据 |

`stats` 只给 Go 记录，不一定发给模型。

## 6. 代码结构

`content.ts` 会越来越大，拆成一个目录：

```
extension/src/snapshot/
  walk.ts         ① 遍历 + 上限
  visible.ts      ② 可见
  interactive.ts  ③ 可交互（isInteractive）
  occlusion.ts    ④ 遮挡
  group.ts        ⑤ 合并
  privacy.ts      ⑥ 隐私过滤（纯函数）
  links.ts        网址解码显示（纯函数）
  text.ts         文字清理、截断（纯函数）
  serialize.ts    ⑦a / ⑦b 输出
```

**纯函数和依赖页面布局的函数分开。** `links.ts`、`text.ts`、`privacy.ts` 不碰 DOM 布局，可以用单元测试覆盖（用 vitest，不需要浏览器）。依赖 `getBoundingClientRect`、`elementFromPoint` 的部分保持薄，靠真实页面验证。browser-use 修坑 5 时做的第一件事，就是把转换逻辑抽成纯函数补测试。

## 7. 怎么验证

1. **单元测试**：纯函数，覆盖中文 URL、不合法的 `%` 序列、超长文字、手机号打码等情况。
2. **真实页面对比**：每次改规则，在同几个页面上跑一次，对比 `stats` 和输出：
   - 淘宝首页（未登录）
   - 淘宝搜索结果页（登录小号）
   - 淘宝商品详情页
   - 京东搜索结果页
   - 至少一个非电商网站（比如 GitHub 仓库页、一篇新闻）：验证规则确实是通用的
3. **检查隐私**：在登录状态下跑完，搜索输出里有没有账号昵称、手机号。
4. **记录数字**：每个页面的原始大小 → 输出大小、商品数、耗时，记在本文档末尾的表格里。

快照文本**不保存到仓库里**：登录状态下的输出可能含个人信息。要保存测试样本，先过一遍隐私过滤，并人工检查。

## 8. 分阶段

每个阶段结束都在真实页面上量一次。

| 阶段 | 内容 | 预期效果 |
|---|---|---|
| **P1** | 去掉 href、网址解码、`text.ts`、属性白名单和去重、⑤ 合并成一行、头部统计、隐私正则 | 首页数据：预算能装下约 5 倍元素；搜索页：一个商品一行 |
| P2 | 状态文字、② 计算样式和视口窗口、④ 遮挡、`snapshotId` 和过期检查、硬上限、`link(编号)` | 模型看得懂页面状态；弹窗下面的元素不再出现；点击不会点错 |
| P3 | `read` 命令（通用分块）、Go 侧小模型按 schema 提取、策略表机制（第 4 节）和实测证明需要的第一批策略 | 能从任意列表页拿到结构化数据；淘宝等页面通过策略更精确 |
| P4 | 滚动加载、骨架屏提示、性能压测、隐私词表 | 懒加载的内容也能拿到；昵称不再发给模型 |

P1 改动最小、收益最大，先做。
