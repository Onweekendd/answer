# 「买不买」产品定位

2026-10-21 定。依据是两轮小红书调研（只读、低频，用我们自己的浏览器插件看的）和社区里的真实帖子。以后做取舍时拿它对照；有新证据推翻它时改这份文档，不要只改代码。

## 一句话

**花钱之前，让大家帮你把把关，让 AI 帮你做功课。**

用户发一个「想花这笔钱」的帖子：社区投票「通过 / 驳回」，AI 用用户自己的浏览器去小红书看真实的人怎么说、去各个平台比真实的价格，交一份带出处的决策材料。最后由用户自己决定。

## 两种需求，两样东西各管一样

社区里的真实帖子（2026-10-21）说明，「要不要花」背后是两件不同的事：

| 帖子 | 金额 | 用户真正要的 | 谁能帮上 |
|---|---|---|---|
| 鼠标小配饰 | ¥69 | 已经想买了，要有人同意 | 社区 |
| 一个人吃的饭 | ¥120 | 被理解、被陪伴 | 社区 |
| 托特包 | ¥230 | 要不要买 + 便宜的怕质量差、哪个颜色耐用 | 社区 + AI |
| 瑜伽教练培训 | ¥17800 | 机构的「认证」真不真、行业值不值得入、定金退了亏 600 还是降级 | AI |

- **情绪和克制（要不要花）**：小额、冲动型。社区的价值，「钱包等一等」这类小程序做的就是这个。
- **信息和判断（值不值、买哪个）**：金额越大、越陌生越需要。AI 做功课的价值，社区和「钱包等一等」都做不到。

AI 按金额和问题决定做多少功课：小额的只说现在是不是好价、有没有平替；大额、陌生的做深度调研，出一张决策表。

## 给谁

家里负责采购的人，以及要做一笔不熟悉、价格不低的消费的人。不按品类划分：同一个人今天买娃的东西，明天给爸妈买手机，下个月装修。

## 「购物」包括什么

不只是网购。装修、旅行、培训、本地服务都是花钱之前的决策，结构相同：要花一笔钱 → 看真实的人的经验 → 跨平台比选项和价格 → 做决定。

大项目 = 很多个单件决策 + 它们之间的约束（预算、尺寸、时间、路线）+ 一份汇总。所以先把单件决策做扎实，大项目在它上面加「拆解」和「汇总」两层，做成场景模板（装修软装清单、待产包、出行攻略整合）。

顺序：商品 → 价格透明的体验（酒店、门票）→ 服务（施工队、家政：没有型号可比，信息源是反爬很严的大众点评）。

## 为什么是我们

1. **用用户自己的浏览器**：看得到小红书上真实的人的经验。云端 Agent 进不去，用户自己在评论里说「Agent 推理弱是因为没有小红书这个信息源」「Claude 给的全是 TripAdvisor 上给外国人的路线」。
2. **站在消费者这边**：跨平台、差评照摆、不推广告。平台自带的 AI 不会推荐别家，也被用户觉得「像广告」。
3. **每一条都有出处**：点开就是原帖、原商品。信任来自真实的人，不来自 AI。
4. **社区**：真实的人的判断和陪伴，这是纯 AI 产品没有的。

## 我们不是什么

- **不是通用 Agent**：只做花钱之前的调研和把关。
- **不替用户下单、不付款**：只给链接。
- **不追求最优**：目标是「够好，而且快」。网购已经让人陷进完美主义，我们不能加重它。
- **不靠返佣赚钱**：拿了返佣就失去中立，而中立是最大的优势。

## 产品原则

1. 先问清楚再查：预算、尺寸、给谁用、最在意什么，两三个问题。
2. 给选项和证据，不替用户拍板。
3. 差评优先：好评能刷，真实差评和追评最难找、最有用。
4. 简洁：一张表能说清的不写一大段。
5. 每条都有出处。

## 证据（小红书，2026-10-21）

| 笔记 | 赞 / 评论 | 说明了什么 |
|---|---|---|

样本偏向愿意发帖吐槽的人，结论要靠下面的验证。

## 验证

1. **社区里的真实帖子**：挑一个金额大、信息问题多的帖子（比如瑜伽培训），由 AI 助手真正做一次功课回在帖子下面，看作者的反应。
2. **社区帖子的分布**：多少是百元以内的冲动消费，多少是千元以上需要调研的。后者的比例决定 AI 做功课的需求有多大。
3. **小红书发帖**：「免费帮你做花钱前的功课」，看来的人多不多、想买什么、拿到决策表以后用不用。

## 已有的东西放在哪

| 已有的 | 在定位里的位置 |
|---|---|
| 浏览器插件 + 站点策略 | 去各个平台做功课 |
| 收割、商品卡片 | 收集候选和价格 |
| 沙箱 | 整理成决策表、清单、方案板 |
| 对话日志、重放 | 决策过程能回看、能继续追问 |
| 社区投票、帮发帖 | 把关和陪伴；决策表一键发到社区 |

要新做的主要是交付物（一段回答 → 决策表）和提示词（先问清楚、差评优先、给选项、按金额决定功课深度）。
